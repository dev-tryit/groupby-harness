# 이력서 조사

이력서에 실제로 무엇이 담기는지를 조사한 문서. 근거는 `01_problem/problem.md`의 1.3 "용어"와 `CHECKLIST.md`의 "`03_prd`의 핵심 알고리즘"에 남은 항목 "목업 이력서에 경력 기술을 포함할지"다. 과제는 이력서에 무엇을 담을지 정해 주지 않았다.

확인한 날짜는 2026-10-11이다.

## 1. 결론

- 사람인의 이력서에는 사실의 목록(학력, 경력, 스킬) 말고도 서술을 적는 항목이 따로 있다. 경력기술서와 자기소개서는 이력서 안의 추가 항목이다(2장).
- 고객사가 받는 서류는 공고마다 다르다. 실제 공고 6건 가운데 이력서만 받는 공고가 1건, 경력기술서를 따로 받는 공고가 1건이다(3장).
- 실제 공고 8건 가운데 6건에 서술형 조건("해 봤는가", "할 수 있는가")이 있다. 이력서에 한 일의 서술이 없으면 이 조건들은 모두 "알 수 없음"이 된다(해석, 4장).
- 추천 후보는 경력마다 담당 업무를 몇 줄 적은 이력서다. 정하는 것은 사용자다(4장).

## 2. 사람인의 이력서 항목

사람인의 도움말에서 확인한 것이다([사람인 도움말](https://www.saramin.co.kr/zf_user/help/help-word/view?idx=350)). 도움말은 추가 항목만 설명한다.

| 항목 | 적는 것 |
| :- | :- |
| MY Career | 직무, 핵심 역량, 전공, 스킬, 경력, 경험을 간단히 정리한 소개 |
| 스킬 | 직무 역량, 기술, 도메인 지식. 직종에 맞춰 추천된 단어를 고르거나 직접 적는다. |
| 경험/활동/교육 | 교내 활동, 인턴, 자원봉사, 동아리, 아르바이트, 수행 과제, 해외 연수, 교육 이수 |
| 포트폴리오 및 기타 문서 | 파일. 지원할 때 고른 파일만 함께 제출된다. |
| 경력기술서 | 서술. 양식이 네 가지다: 프로젝트형, 개발 기술형, 디자이너형, 영업 성과형 |
| 자기소개서 | 서술 |
| 인적성검사 | 검사 결과 |
| 취업 우대사항 | 고용지원금, 보훈, 병역 |

- 필수 항목(기본 정보, 학력, 경력)의 입력 칸은 도움말에 설명이 없다. 경력 항목에 담당 업무를 적는 칸이 있는지는 확인하지 못했다.
- 희망 근무 조건 항목은 도움말에 나오지 않았다.
- 검색 요약으로 확인한 것: 고용노동부의 직무 능력 중심 입사지원서 표준 양식은 "경력"(보수를 받고 일한 것)과 "경험"(보수 없이 한 활동)을 나눈다.
- 검색 요약으로 확인한 것: 공공기관의 서류 심사 기준은 경력증명서에 담당 업무가 적혀 있어야 직무 관련성을 확인할 수 있다고 적는다.

## 3. 공고가 받는 서류

실제 공고에서 확인한 것이다(`posting/posting.md` 5.2).

- 이력서만 받는 공고가 있다. 이력서와 자기소개서, 이력서와 자기소개서와 포트폴리오, 이력서와 자기소개서와 경력기술서를 받는 공고도 있다.
- 한 공고는 이력서에 희망 연봉을 적으라고 했다.

## 4. 목업 이력서에 무엇을 담을지의 선택지

| 선택지 | 담는 것 | 장점 | 단점 |
| :- | :- | :- | :- |
| 가 | 사실의 목록만. 학력, 경력(회사, 직무, 기간), 자격증, 스킬 | 용어의 정의(`problem.md` 1.3)에 가장 가깝다. 만들기 쉽다. | 서술형 조건을 확인할 재료가 스킬 단어뿐이다. 실제 공고의 조건 대부분이 "알 수 없음"이 된다. |
| 나 | 사실의 목록에 경력마다 담당 업무 몇 줄 | 서술형 조건을 인용으로 확인할 수 있다. 이력서만 받는 공고의 상황과 맞는다. | 이력서와 경력기술서의 경계가 흐려진다. |
| 다 | 사실의 목록과 따로 쓴 경력기술서 | 사람인의 항목 구성과 같다. | 과제가 말하지 않은 서류를 더하게 된다. |

추천 후보는 나다. 이유는 세 가지다.

- 실제 공고의 서술형 조건을 판정하려면 한 일의 서술이 있어야 한다. 가로는 부분 매칭 3명을 서로 다른 방식으로 만들 자리가 없다.
- 근거는 이력서의 구절을 인용해야 한다(`CHECKLIST.md`의 "`03_prd`의 핵심 알고리즘"). 인용할 문장이 이력서에 있어야 한다.
- 이력서에 조건이 다른 칸 아래에 적혀 있을 때 LLM이 놓친 사례가 있다(`matching/matching.md` 12.3). 칸이 있는 이력서여야 이 경우를 테스트할 수 있다.

걸리는 점은 과제가 "목업 이력서"라고만 했다는 것이다. 어디까지를 이력서로 볼지는 사용자가 정한다.

## 5. 확인하지 못한 것

- 사람인 이력서의 필수 항목(기본 정보, 학력, 경력)의 입력 칸. 로그인해야 보이는 화면이라 보지 않았다.
- 고객사가 사람인에서 받은 지원서를 어떤 형식으로 내려받는지.
- 고용노동부 표준 양식의 원문.
- 직군에 따라 이력서에 적는 것이 얼마나 다른지.
