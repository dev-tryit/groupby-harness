# 법 조사

채용 공고를 가져오는 일과 관련된 국내 법과 판례를 조사한 문서. 근거는 `01_problem/problem.md`의 제약 "법"과 1.1 "만들 서비스"다.

이 문서는 공개된 기사와 법무법인의 자료를 읽고 정리한 것이다. 법률 자문이 아니다. 판결문 원문은 읽지 못했다. 확인한 날짜는 2026-10-10이다.

## 1. 결론

- 서비스 제공사가 채용 플랫폼의 공고를 모아서 쌓는 구조는 판례에서 진 구조다(잡코리아–사람인).
- 형사에서 무죄가 나와도 민사에서 부정경쟁행위로 배상할 수 있다(야놀자–여기어때).
- 그래서 기준은 데이터가 어디에 있느냐가 아니라 누가 가져와서 넣었느냐다.
- 고른 구조는 수집이 고객사 쪽에서 일어나는 구조다. 사람인에 접속하는 것은 고객사이고, 서비스 제공사는 고객사가 넘긴 것만 받는다(4장).
- 고객사가 주소를 넣고 서비스 제공사의 서버가 그 한 건을 가져오는 구조에는 문제가 남는다(4장).

## 2. 관련된 법

| 법 | 조항 | 무엇을 막는가 |
| :- | :- | :- |
| 저작권법 | 제93조 (데이터베이스제작자의 권리) | 데이터베이스의 전부 또는 상당한 부분을 복제·배포·전송하는 것. 개별 소재를 반복적·체계적으로 복제해 같은 결과가 되는 것도 포함한다. |
| 부정경쟁방지법 | 제2조 제1호 (파)목 (성과 도용. 2022-04-20 전에는 (카)목) | 남이 상당한 투자와 노력으로 만든 성과를 무단으로 자기 영업에 쓰는 것 |
| 정보통신망법 | 제48조 제1항 (정보통신망 침입) | 접근권한 없이, 또는 허용된 접근권한을 넘어 정보통신망에 들어가는 것 |
| 형법 | 컴퓨터등장애업무방해죄 | 부정한 명령 등으로 정보처리에 장애를 일으켜 업무를 방해하는 것 |

## 3. 판례

### 3.1 잡코리아–사람인

사람인이 피고다. 이 과제가 가져오라고 한 사람인이, 같은 일을 하다가 진 당사자다.

| 항목 | 내용 |
| :- | :- |
| 한 일 | 사람인이 잡코리아에 올라온 채용 공고를 자동으로 수집해 자기 사이트에 실었다. 출처 표시를 지웠다. VPN으로 IP를 나누어 접속했고 robots.txt를 확인하지 않았다. |
| 판단 | 데이터베이스제작자의 권리 침해와 부정경쟁행위를 인정했다. 정상적인 검색 로봇의 수집은 허용되지만, 정체를 숨기고 출처를 지운 채 복제하는 것은 허용되지 않는다고 보았다. |
| 결과 | 2017년 4월 항소심 판결이 그해 대법원에서 확정되었다. 사람인이 낸 돈은 4억 5천만 원이다(손해배상 2억 5천만 원, 앞선 법원 조정을 어긴 대가 2억 원). 수집한 것을 폐기하라는 명령도 받았다. |
| 확인하지 못한 것 | 사건번호, 정확한 선고일 |

### 3.2 야놀자–여기어때

| 항목 | 내용 |
| :- | :- |
| 한 일 | 여기어때 쪽이 야놀자의 API 서버를 호출해 숙박업소 정보를 수집했다. |
| 형사 | 1심 유죄(서울중앙지방법원 2020-02-11 선고 2019고단1777), 항소심 무죄(서울고등법원 2021-01-13 선고 2020노611), 대법원 무죄 확정(2022-05-12 선고 2021도1533). |
| 형사에서 무죄가 된 이유 | 정보통신망 침입: 접근을 막는 보호조치가 없었고, 약관의 제한이 비회원에게 적용되기 어려웠다. 데이터베이스제작자의 권리: 약 50개 항목 중 3~8개만 수집했고 대부분 이미 공개된 정보였다. 반복적·체계적 복제는 상당한 부분을 복제한 것과 같은 결과가 되어야 인정된다. 업무방해: 정보처리 장애가 실제로 생겼다고 볼 수 없었다. |
| 민사 | 1심(서울중앙지방법원 2021-08-19 선고 2018가합508729)이 부정경쟁행위를 인정해 10억 원을 배상하라고 했다. 이 배상이 유지되었다는 자료가 있으나 상급심의 사건번호는 확인하지 못했다. |
| 자료가 말하는 주의점 | 무죄를 일반화하면 안 된다. 크롤링 금지 문구나 명시적인 약관 제한이 있거나, 회원 계정으로 대량 수집해 영리에 쓰면 결론이 달라질 수 있다. |

### 3.3 두 판례에서 읽은 것

- 위험을 키우는 것: 대량으로 가져온다, 통째로 옮겨 싣는다, 출처를 지운다, 정체를 숨긴다, 상대와 경쟁 관계다.
- 형사와 민사는 따로 간다. 형사에서 무죄여도 민사에서 부정경쟁행위가 인정될 수 있다.
- 한 번에 조금씩 가져와도, 반복해서 결과적으로 상당한 부분이 되면 문제가 된다.

## 4. 구조별 판단

판례를 읽은 해석이다.

| 구조 | 사람인에 접속하는 주체 | 판단 |
| :- | :- | :- |
| 서비스 제공사가 사람인을 돌며 모아 쌓는다 | 서비스 제공사 | 잡코리아–사람인 사건과 같은 구조다. 과제가 "법적으로 문제가 될 수 있다"고 한 것이다. |
| 고객사가 자기 공고의 주소를 넣으면 서비스 제공사의 서버가 그 한 건을 가져온다 | 서비스 제공사 | 문제가 남는다. 아래 세 가지다. |
| 수집기가 고객사 쪽(고객사의 PC나 브라우저)에서 돈다 | 고객사 | **고른 구조다.** 과제의 "고객사를 거쳐서 들어오는 구조"에 해당한다고 읽었다. 서비스 제공사는 도구를 제공하고 고객사가 넘긴 것만 받는다. |
| 고객사가 자기 공고(이미지)를 직접 넣는다 | 없음 | 가장 안전하다. 크롤링이 사라지므로 과제의 "우회"라는 말과는 덜 맞는다. |

주소 한 건을 가져오는 구조에 남는 문제는 세 가지다.

- 접속하는 주체: 고객사 한 곳에게는 한 건이지만, 서비스 제공사 전체로는 반복적이고 체계적인 수집이 된다.
- 경쟁 관계: 서비스 제공사도 채용 서비스다. 민사의 부정경쟁행위(성과 도용)는 경쟁 관계에서 문제가 된다.
- 공고의 주인 확인: 주소만 받으면 누구나 남의 공고 주소를 넣을 수 있다. 그러면 "고객사가 자기 공고를 넣었다"는 전제가 깨진다.

고른 구조에서 읽기(OCR)를 어느 쪽에 둘지는 법이 아니라 기술의 문제로 보았다. 법적으로 필요한 경계는 수집까지다.

| | 읽기를 고객사 쪽에 둔다 | 읽기를 서비스 제공사의 서버에 둔다 |
| :- | :- | :- |
| 서비스 제공사가 받는 것 | 읽은 글자 | 고객사가 보낸 이미지 |
| 얻는 것 | 공고 원본(이미지)을 서비스 제공사가 갖지 않는다. 경계가 가장 분명하다. | 읽기의 품질을 서비스 제공사가 관리하고, 틀리게 읽은 것을 원본과 대조할 수 있다. |
| 잃는 것 | 서버가 원본을 볼 수 없어 읽기가 틀렸는지 확인하기 어렵다. 읽기에 LLM을 쓰면 그 호출을 고객사 쪽에서 어떻게 할지가 문제다. | 이미지가 서비스 제공사로 넘어온다. |

고객사 쪽에서 읽은 것을 올리는 방향으로 보고 있고, 이미지를 읽는 방법과 비용을 조사한 뒤에 정한다.

고른 구조에도 문제가 남는다.

- 사람인의 기업회원 약관 제23조 제3항이 자동화된 수단(크롤링 등)으로 접근하는 것과 정보를 전부든 일부든 수집하는 것을 금지한다(`crawling/crawling.md` 6장에서 확인). 고객사는 사람인의 기업회원이므로, 고객사 쪽에서 수집해도 고객사가 이 조항을 어기게 될 수 있다. 해석이다.
- 같은 약관 제23조 제1항은 기업회원이 올린 게시물의 저작권이 올린 기업회원에게 있다고 적는다. 그래서 고객사가 자기 공고의 원본 이미지를 직접 넣는 구조에서는 제23조 제3항이 문제가 되지 않는다.
- 서비스 제공사가 수집 도구를 만들어 제공한다는 점에서 책임이 없어지는지는 확인하지 못했다.

## 5. 사람인의 robots.txt

2026-10-10에 `https://www.saramin.co.kr/robots.txt`를 확인했다. 원문을 그대로 옮긴 것이 아니라 요약이다.

- GPTBot과 Bytespider는 사이트 전체가 금지다.
- 그 밖의 크롤러에게는 로그인, 이력서, 지원 관리, 인재풀, 광고, 헤드헌팅 관련 경로가 금지다.
- 채용 공고 상세(`/zf_user/jobs/` 아래)는 전체가 금지되어 있지 않다. 헤드헌팅 공고 보기와 `/zf_user/jobs/view/etc`는 금지이고, `/zf_user/jobs/relay/recruit-view` 등은 명시적으로 허용이다.
- robots.txt는 권고다. 허용되어 있다고 해서 수집한 것을 쓰는 일까지 허용된다는 뜻은 아니다.

## 6. 다른 서비스: 직행

여러 채용 공고를 한곳에 모아 보여주는 통합 검색 서비스다.

- 확인한 것: 통합 검색 서비스로 분류된다. 직업정보제공사업 신고를 한 사업자다. 이 신고는 사업을 할 자격이고 수집 방식이 적법하다는 뜻이 아니다.
- 확인하지 못한 것: 공고를 어떻게 모으는지(크롤링인지, 제휴인지), 공고를 누르면 원문으로 보내는지.
- 추측: 공고를 통째로 싣지 않고 원문 링크로 보내면 원래 사이트에 방문자를 돌려주는 검색엔진에 가깝다. 사람인이 진 사건은 출처를 지우고 통째로 옮겨 실은 경우였다. 소송이 없다는 것과 적법하다는 것은 다르다.
- 우리 서비스와의 차이: 직행은 구직자에게 공고를 찾아 주는 서비스다. 우리 서비스는 고객사가 자기 공고 하나에 지원자를 매칭하는 서비스다. 공고를 모을 이유가 없다.
