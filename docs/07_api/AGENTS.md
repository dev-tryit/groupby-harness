# 07_api

API 구조를 정하는 단계. 백엔드가 바깥과 데이터를 주고받는 방식을 모두 정한다.

## 프론트엔드와 백엔드 사이

통신의 성격에 따라 세 폴더로 나눈다.

| 폴더 | 통신의 성격 | 해당 기술 |
| :- | :- | :- |
| `request-response/` | 요청-응답. 클라이언트가 물어볼 때만 서버가 답한다. | HTTP, 폴링 |
| `server-push/` | 서버 푸시. 서버가 클라이언트에게 한쪽 방향으로 계속 보낸다. | SSE |
| `bidirectional/` | 양방향. 양쪽이 서로 실시간으로 주고받는다. | WebSocket |

- 기능마다 누가 먼저 보내는지와 얼마나 실시간이어야 하는지를 보고 성격을 정한다. 기술은 성격에서 따라 나온다.
- 폴링은 폴더를 따로 두지 않는다. 폴링은 요청-응답을 반복하는 것이므로, `request-response/`의 해당 엔드포인트 문서에 폴링으로 호출한다는 것과 호출 주기를 속성으로 적는다.

## 그 밖의 통신

| 폴더 | 내용 |
| :- | :- |
| `external/` | 외부 연동. 결제, 알림, 소셜 로그인처럼 백엔드가 바깥 서비스와 주고받는 통신. |
| `background/` | 백그라운드 작업. 사용자의 요청 없이 시간이나 이벤트로 시작되는 작업 (예약 작업, 배치, 이벤트를 받아 처리하는 작업). |

- 백그라운드 작업은 호출하는 클라이언트가 없지만 백엔드로 들어오는 진입점이므로 이 단계에서 함께 정한다. 이벤트로 시작되는 작업은 `06_data-model/event/`의 어느 이벤트를 받는지 적는다.
