# 12_log

로그를 설계하는 단계. 무엇을 어떤 형태로 남길지를 코드를 쓰기 전에 정한다.

- 로그는 일관되게 쓴다. 로그 메시지의 형태가 일관되어야 무슨 일이 일어났는지 파악하기 쉽다.
- 모든 로그 메시지는 같은 형태를 따른다. 형태는 이 단계에서 한 번 정하고, 프론트엔드와 백엔드가 같은 형태를 쓴다.
- 요청 하나에서 나온 로그를 끝까지 따라갈 수 있도록 모든 로그에 trace id를 넣는다. trace id는 프론트엔드, 백엔드, 백그라운드 작업, 외부 연동을 거치는 동안 그대로 이어져야 한다.
- 로그에 남기면 안 되는 정보와 반드시 남겨야 하는 기록은 `11_security`를 따른다.
