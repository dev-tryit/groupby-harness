# 09_infra

인프라 구조를 정하는 단계. 앞 단계에서 정한 성격을 보고 그것을 담을 기술을 고른다. 성격이 먼저이고 기술 선택이 나중이다.

- `06_data-model`의 데이터를 보고 그것을 담을 기술(DB, 파일 저장소, 메모리 DB, pub/sub)을 고른다.
- `07_api`의 통신 성격(요청-응답, 서버 푸시, 양방향, 외부 연동, 백그라운드 작업)을 보고 그것을 받칠 구성을 고른다.
- `08_algorithm`이 요구하는 성능을 낼 수 있는 구성을 고른다.
- 고른 기술에 맞는 실제 스키마도 이 단계에서 정한다. DB 종류에 따라 저장 구조가 달라지기 때문이다.
- CI/CD는 GitHub Actions를 최대한 활용한다. 어느 브랜치에서 무엇을 돌리는지를 이 단계에서 정한다. 브랜치 전략은 `commit-reports/AGENTS.md`에 있다.
