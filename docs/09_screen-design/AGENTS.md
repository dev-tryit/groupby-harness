# 09_screen-design

화면설계도의 목적은 프론트 코드를 만들기 위한 그림을 그리는 것이다.

- 이 단계의 산출물을 보고 프론트 코드를 바로 구현할 수 있어야 한다.
- 큰 그림은 `04_wireframe`에서 이미 정했다. 여기서는 그 큰 그림을 따르면서 화면 하나하나를 구현에 필요한 수준으로 구체화한다.
- 색, 톤, 분위기는 `05_branding`에서 정한 브랜딩을 따른다.
- 화면설계도는 설명서를 만드는 것이 아니다. 실제로 프론트엔드를 만드는 것이 목적이다. 그래서 산출물은 실제로 동작하는 화면이다.
- HTML로 만든다. 문서의 이름은 `screen-design.html`이다. 가능하면 HTML 하나로 만든다. 바깥의 자원을 불러오지 않는다.
- 하이파이(hi-fi)로 만든다. 브랜딩의 값과 API의 요청을 그대로 쓴다. 서버 없이 파일로 열어도 보이도록 미리보기 데이터를 넣어 둔다.
- 만들 때 `frontend-design` 스킬을 반드시 쓴다.
- 와이어프레임을 그대로 옮기지 않는다. 와이어프레임은 기능의 관점이고 화면설계도는 미적 관점이다. 기능은 와이어프레임을 따르되, 보기 좋게 하려고 더할 것은 더한다.
- 사용자에게 필요한 정보와 그렇지 않은 정보를 구분한다. 필요한 정보를 먼저 보이고, 그렇지 않은 정보는 뒤로 보내거나 눌러야 보이게 한다.
- 화면은 `05_branding`의 컴포넌트를 최대한 활용해 만든다.
- 화면에 설계의 설명을 붙이지 않는다. 구현의 조건은 파일 맨 위의 주석과 `DECISIONS.md`에 적는다.
