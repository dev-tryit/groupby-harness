## 2026-10-11 19:30 — `infra.md`를 씀

**무엇을 바꿨는지**

- 앞 단계에서 받은 성격, 고른 기술, 구성(컨테이너 둘), 저장 구조, 정해야 하는 것(크롤링의 재현, 예산)을 적었다.
- 3~6장은 에이전트의 추천안이라고 맨 위에 적었다.

**왜 바꿨는지**

- 사용자가 `05`~`11`을 진행하라고 했다. 근거는 `06_data-model`, `07_api`다.
- 파일 저장소를 고른 이유: 양이 적고 동시에 쓰는 일이 없다. 관계형 DB는 컨테이너와 스키마 관리가 늘어나는데 얻는 것이 없어 버렸다.
- 컨테이너를 둘로 나눈 이유: 프로그램이 둘이고, `server`가 `data/client`를 보지 못하게 해서 이미지가 넘어가지 않는다는 것을 구성으로 지킨다. 하나로 합치는 것이 더 단순하지만 이 경계가 사라져 버렸다.
- 크롤링의 재현과 예산은 정하지 않았다. 사용자가 정할 것이라 선택지와 추천 후보만 적었다.

**영향을 받는 다른 단계**

- `09_screen-design`: 정적 파일로 만든다.
- `10_security`: 키를 넣는 방식, 포트, 컨테이너가 보는 폴더가 대책이 된다.
- `13_code`: Docker Compose 구성과 HTTP 서버를 만든다.

## 2026-10-11 19:32 — 크롤링의 재현을 정함 (`infra.md` 2장, 6.1)

**무엇을 바꿨는지**

**영향을 받는 다른 단계**

- `10_security`: S3의 대책을 고쳤다.
- `13_code`: 인프라 서브모듈의 `.gitignore`를 고쳤다. README의 "실행 방법"에 저장된 결과를 지우는 방법을 적어야 한다.

## 2026-10-11 19:57 — 4장 "구성"을 배치 다이어그램으로 바꿈 (`infra.md`)

**무엇을 바꿨는지**

- 4장의 글자 그림을 배치 다이어그램으로 바꿨다. 평가자의 컴퓨터 안에 Docker Compose(컨테이너 둘)와 로컬 디스크(폴더 다섯)가 있고, 바깥에 사람인과 OpenAI가 있다. 선마다 읽기만 하는지, 쓰는지, 어떤 통신인지를 적었다.
- 컨테이너는 root가 아닌 사용자로 실행하고, 쓸 일이 없는 폴더는 읽기 전용으로 붙인다고 적었다. `.env`를 이미지를 만드는 재료에서도 뺀다고 적었다.
- `AGENTS.md`에 구성은 배치 다이어그램으로 그린다는 규칙을 더했다.

**왜 바꿨는지**

- 사용자가 인프라를 UML로 그리자고 했고, 논의한 결과 배치 다이어그램으로 정했다. 인프라는 무엇이 어디에 올라가는지를 보는 것이라, 부품과 인터페이스를 보는 컴포넌트 다이어그램보다 맞다.
- mermaid에 배치 다이어그램이 따로 없어 상자 안에 상자를 넣는 방식(`flowchart`의 `subgraph`)으로 그렸다. GitHub에서 그림으로 보이게 하려는 것이다.
- 사용자와 읽기 전용은 `14_report/report.md`의 R8이다.

**영향을 받는 다른 단계**

- `10_security`: 선이 없다는 것(`server`와 `data/client`, `server`와 사람인)과 읽기 전용이 대책이 된다.
- `13_code`: Docker Compose 구성을 이 그림대로 만든다.

## 2026-10-11 20:15 — 저장 구조를 앞 단계의 키에 맞춤 (`infra.md` 5장)

**무엇을 바꿨는지**

- 저장하는 필드를 새 키로 고쳤다(`image_id`, `slice_id`, `item_id`와 `no`). 비교의 파일에서 `posting_id`를 뺐다.
- 키의 값을 어떻게 만드는지를 적었다. 전체에서 겹치지 않는 문자열이고 뜻이 없다. `resume_id`는 이력서의 파일 이름이다.
- 경로의 폴더가 FK의 역할을 한다고 적었다. 경로는 바꾸지 않았다.

**왜 바꿨는지**

- 앞 단계 `06_data-model/persistent`에서 1:N인 자식이 자기만의 PK를 갖게 되었다.
- 경로를 그대로 둔 이유: 공고 하나의 이력서와 비교를 폴더 하나로 집어내는 것이 읽는 길에 맞고, 바꾸지 않아도 새 키와 어긋나지 않는다. 고치는 범위가 가장 작다.

**영향을 받는 다른 단계**

- `12_test-scenario`: 골든셋의 이력서 파일 이름이 공고마다 `resume-1`부터라 겹친다. 겹치지 않게 바꿔야 한다.
- `13_code`: 저장된 파일과 코드.
