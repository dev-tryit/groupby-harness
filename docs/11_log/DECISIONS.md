## 2026-10-11 19:40 — `log.md`를 앞 단계와 맞추고 보강함

**무엇을 바꿨는지**

- 1장 "로그로 답하려는 질문"을 더했다. 남기는 일의 목록이 어디서 나왔는지를 보이려는 것이다.
- trace id의 흐름에 "프로그램의 실행"을 더했다. `run.started`와 `run.finished`는 공고 하나에 속하지 않아 쓸 trace id가 없었다. 넘긴 것에 `trace_id`가 없는 경우와, 받은 `X-Trace-Id`의 모양이 어긋난 경우도 적었다.
- 공고 하나를 trace id로 따라간 모습을 예로 더했다.
- `run.finished`에 LLM 호출 수와 비용의 합을 더했다. `http.requested`와 `stage.skipped`에 무엇에 대한 것인지(`purpose`, `stage`)를 더했다. `ranking.computed`를 지웠다.
- `10_security/security.md` 4장이 반드시 남기라고 한 것과 로그의 대응표를 더했다.
- "표준 출력에는 로그만 낸다"를 적었다.

**왜 바꿨는지**

- 사용자가 로그까지 잘 고민하면서 정합성을 맞추라고 했다.
- 모든 로그에 trace id가 있어야 하는데(`AGENTS.md`) 실행 단위의 로그가 빠져 있었다.
- `ranking.computed`를 지운 이유: 점수와 순위는 저장하지 않고 응답을 만들 때 계산한다(`06_data-model/persistent/persistent.md` 2장). 요청마다 남으면 `api.requested`와 겹친다.
- 표준 출력에 로그만 내는 이유: 앞에서는 "로그와 결과를 섞지 않는다"고만 적어 어디로 나눌지가 없었다. 결과를 보여 주는 자리는 화면이다.
- 필드의 이름을 앞 단계와 같게 쓴다고 적은 이유: 로그의 번호로 저장된 결과를 찾아야 한다.

**영향을 받는 다른 단계**

- `13_code`: 지금 코드는 `print`로 랭킹을 글자로 출력한다. 이 형태로 맞춰야 한다.
