# 보안

앞 단계(`00`~`09`)를 하나하나 보면서 보안의 허점을 체크하고 막은 것을 적은 문서. 보안 목표는 `03_prd/prd.md` 4장을 따른다.

## 1. 지킬 것

`03_prd/prd.md` 4장의 다섯 가지다. OpenAI 키, 타인의 연락처, 공고의 이미지, 점수와 판정, 지원자의 이력서.

## 2. 앞 단계마다 본 것

단계마다 무엇을 보았는지, 어떤 허점이 있는지, 무엇으로 막는지를 적는다. "막는 곳"은 그 대책이 적혀 있는 앞 단계의 자리다.

## 3. 막지 못한 것

막으려면 앞 단계를 고쳐야 하는 것은 여기서 고치지 않았다. 어떻게 할지는 사용자가 정한다. 정하면 그 앞 단계부터 내려오며 고친다.

| 허점 | 본 단계 | 지금의 상태 |
| :- | :- | :- |
| 근거로 낸 구절이 이력서에 실제로 있지만 판정을 뒷받침하지 않는다 | `03_prd` | 코드로 잡지 못한다. 사람이 원문과 나란히 보고 잡는다(`03_prd/prd.md` 10.1). 화면이 근거와 원문을 나란히 두는 이유다 |
| 인증이 없어 화면을 여는 사람은 누구나 이력서를 본다 | `03_prd` | 이 과제의 이력서는 목업이다. 실제 서비스라면 인증과 공고별 권한이 필요하다 |
| 고객사 쪽과 서비스 제공사 쪽이 같은 키를 쓴다 | `03_prd` | 과제가 준 키가 하나다. 실제 서비스라면 서로 다른 키다 |
| 내려받는 이미지의 크기와 주소의 호스트에 제한이 없다 | `07_api` | 본문 페이지가 가리키는 주소를 그대로 받는다. 이미지인지만 확인한다 |
| 저장된 특징과 비교의 파일을 누가 고치면 그 판정을 그대로 쓴다 | `08_infra` | 근거가 이력서 안에 있는지도 비교할 때 저장한 값을 쓴다. 그래서 파일에서 판정이나 대조 결과를 고친 것은 잡지 못한다 |
| 이력서에 적힌 지시문이 스스로를 근거로 내게 하면 대조를 통과한다 | `03_prd` | 대조는 구절이 이력서에 있는지만 본다. 프롬프트의 방어 문장으로 줄이지만 보장이 아니다. 방어 문장이 없을 때 지시문만 있는 이력서가 100점을 받았다(`14_report/2026-10-11-2146-resume-injection.html`). 화면에서 근거를 보면 사람이 알아챈다 |
| LLM이 판단하는 과정에서 쓴 글과 대조 결과를 저장한다 | `06_data-model` | 저장하지 않기로 했으나 코드가 저장한다. 저장소에 들어가는 특징과 비교의 파일에 함께 들어 있다. 연락처와 키가 없는 것은 검색해 확인했다 |
