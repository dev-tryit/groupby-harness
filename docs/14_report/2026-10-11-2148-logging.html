로그를 설계대로 만든다

리포트 작성: 2026-10-11 21:48 · 브랜치 v1.0.0
상태: 해결

1. 무엇을 검증했는지

앞 리포트(2026-10-11-2139-code-vs-design.html)의 M5, M8, M9를 사용자가 읽고 지시했다. "로그 형식대로 코드를 짜라", "로그를 보충하라".

2. 무엇이 문제인지

  • 고객사 프로그램이 JSON 로그가 아니라 글을 출력한다. 두 프로그램을 잇는 trace id가 없다.
  • LLM 호출의 토큰 수와 비용, 대조에 실패한 항목이 로그에 남지 않는다.
  • 바깥으로 보낸 요청(사람인)이 로그에 남지 않는다.

3. 영향받는 단계

03_prd(7장의 그림, 8.3) → 06_data-model(넘긴 것의 trace id) → 07_api(background, external) → 08_infra(4장, 5장) → 10_security(3장, 4장) → 11_log → 12_test-scenario → 13_code → result/.

4. 반영 방법

사용자가 정했다. 처음의 로그 설계(11_log/log.md)대로 코드를 만든다. 앞 리포트에서 "만들지 않았다"로 적은 것을 다시 "만든다"로 돌린다.

  • 고객사 프로그램: 글 대신 로그를 낸다. 공고마다 trace id를 만들어 넘긴 것에 담는다.
  • 서비스 제공사 프로그램: 넘겨받은 trace id를 그 공고의 특징 추출과 모든 비교에 쓴다. LLM을 부르면 llm.called(모델, 토큰 수, 비용, 걸린 시간, OpenAI의 요청 번호)를, 저장된 결과를 쓰면 stage.skipped를 남긴다. 대조에 실패한 것은 item.not_in_reading, quote.not_in_resume로 남긴다.
  • 남기면 안 되는 것(키, 이력서의 글자, 근거의 구절, 읽은 내용, 프롬프트)은 그대로 지킨다. 대조 실패의 로그에는 번호만 남긴다.
  • 서비스 제공사 프로그램의 extract, rank 명령은 사람이 읽는 글을 출력하는 그대로 둔다. 컨테이너가 쓰는 것은 serve다.

5. 고친 순서와 결과 (2026-10-11 23:25)

03_prd → 06_data-model → 07_api → 08_infra → 10_security → 11_log → 12_test-scenario(L1~L5, U11을 코드보다 먼저 썼다) → 13_code → result/를 다시 빌드.

  • 두 컨테이너의 출력 39줄이 모두 JSON이고 공통 필드가 있다.
  • 두 공고 모두 고객사 프로그램과 서비스 제공사 프로그램의 로그가 같은 trace id로 이어진다.
  • 저장된 결과가 다 있는 실행에서 stage.skipped가 18번 남고 llm.called가 없다. LLM 호출 수와 비용이 0이다.
  • quote.not_in_resume가 3번 남았다(회계 공고의 resume-6). 번호와 판정만 있고 구절은 없다.
  • 로그에 키, 이력서의 구절, 읽은 내용이 없다.
  • LLM을 실제로 불렀을 때의 llm.called와 사람인에 요청했을 때의 http.requested는 이번 실행에서는 나오지 않았다(저장된 결과가 있어서). 호출을 흉내 낸 자동 테스트 10개로 확인했다.
