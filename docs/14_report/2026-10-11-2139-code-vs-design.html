1. 무엇을 검증했는지

사용자가 "지금의 코드를 기준으로 설계를 맞추라"고 시켰다. result/의 코드, 실행해서 생긴 데이터 파일, 띄운 컨테이너를 설계 문서(01~12)와 하나씩 견주었다.

견준 것은 코드를 만든 에이전트다. docs/AGENTS.md는 검증을 만들지 않은 에이전트의 팀이 하라고 정한다. 이번에는 사용자가 에이전트 팀을 시키지 않았고 대조만 하는 일이라 그대로 했다. 이 점은 사용자가 알아야 한다.

모두 확인한 것이다(코드와 파일을 직접 열어 보았다).

3. 영향받는 단계

01_problem → 03_prd → 04_wireframe → 06_data-model → 07_api → 08_infra → 10_security → 11_log. 09_screen-design과 12_test-scenario는 코드와 같다.

4. 반영 방법

사용자가 방법을 정했다. 코드를 기준으로 설계를 맞춘다. 코드는 고치지 않는다.

  • 설계가 코드보다 나았던 곳(M4의 저장하지 않기, M5의 trace id, M7의 지시 문장, M8의 로그)도 코드가 하는 대로 적는다. 하지 않은 것은 "하지 않았다"고 적고, 왜 필요한지는 남긴다.
  • M7의 지시 문장과 M4의 저장은 보안 문서에서 "막은 것"이 아니라 "막지 못한 것"으로 옮긴다.
  • M11의 와이어프레임 그림은 고친 배치로 다시 그린다.

코드는 고치지 않았다. 설계가 코드보다 나았던 곳은 "만들지 않았다"와 "막지 못했다"로 남겼다. 다음에 코드를 고친다면 이것들이 할 일이다: 프롬프트에 이력서의 지시를 따르지 말라는 문장, 과정의 글과 대조 결과를 저장하지 않기, 고객사 프로그램의 로그와 넘긴 것의 trace id, LLM 호출과 대조 실패의 로그.
