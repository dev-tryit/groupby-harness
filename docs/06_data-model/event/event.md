# 이벤트

한쪽에서 발생해 다른 쪽으로 전달되는 데이터를 적은 문서. 근거는 `03_prd/prd.md`의 7장, 8.3이다.

## 1. 결론

없다.

## 2. 이유

- 고객사 프로그램이 서비스 제공사에 넘기는 것은 이벤트의 성격이 있다. 한쪽에서 생겨 다른 쪽으로 간다. 그러나 이 과제에서는 두 프로그램이 함께 보는 폴더의 파일로 넘긴다(`03_prd/prd.md` 8.3). 그래서 영속 데이터인 "넘긴 것"으로 다룬다(`persistent/persistent.md` 1장의 `SUBMISSION`).
- 전체 과정은 한 번의 실행 안에서 순서대로 진행된다(수집 → 읽기 → 넘기기 → 특징 추출 → 비교 → 점수). 한 단계가 끝난 것을 다른 쪽에 알릴 일이 없다.

## 3. 생기는 경우

- 실제 서비스에서 고객사 프로그램이 서버로 요청을 보내게 되면, "공고가 넘어왔다"가 특징 추출을 시작하게 하는 이벤트가 된다.
- 채용 담당자의 피드백을 받게 되면(`03_prd/prd.md` 11장), 동의와 수정이 이벤트가 된다.
