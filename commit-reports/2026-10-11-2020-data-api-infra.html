무엇을

06_data-model, 07_api, 08_infra의 설계 문서를 썼다.

왜

사용자가 05~11을 진행하라고 했다. 쓰는 동안 사용자가 형식을 정했다. 데이터 모델은 UML로(필드, PK, FK, 구성의 근거, 저장할 것만, 조인 고려), API는 요청마다 하는 일·입력·출력으로, 인프라는 배치 다이어그램으로.

어떻게

  • 데이터 모델: 데이터 9개의 다이어그램. 1:1은 PK이자 FK, 1:N은 자식의 PK와 부모의 FK, JUDGMENT는 이력서와 조건 사이의 관계 테이블이다. 점수와 대조 결과처럼 계산되는 값은 저장하지 않는다. 휘발성 데이터와 이벤트는 없다.
  • API: 화면의 요청 셋(공고의 목록, 공고와 랭킹, 지원자 한 명)을 ReqParam, ResResult 클래스로 적었다. 바깥으로 나가는 요청 다섯과 백그라운드 작업 둘도 같은 형식이다.
  • 인프라: 컨테이너 둘(client, server), 파일 저장소, 포트 127.0.0.1:8000. 사용자가 원래는 클라우드로 해야 하지만 지금은 Docker Compose에서 가능한 선으로 만든다고 정했다.
  • 크롤링의 재현: 사용자가 특징과 비교의 결과를 저장소에 넣기로 정했다.
  • 다이어그램은 렌더링해서 확인했다. 인프라의 고른 기술과 구성은 에이전트의 추천안이다.
