명령 하나로 실행되는 결과물

보고서 작성: 2026-10-11 20:52 · 브랜치 v1.0.0 · 커밋 4개 (서브모듈 3개, 이 레포 1개)

무엇을

API와 HTTP 서버, Docker Compose, 프론트엔드 화면을 만들고, 평가자가 볼 것만 모은 result/를 더했다. README를 result/ 기준으로 다시 썼다.

왜

과제의 요구사항 6(명령 하나로 실행)과 7(UI)이 충족되지 않았고, README에 "작성 예정"이 남아 있었다. result/와 README의 방침은 사용자가 정했다.

어떻게

  • 설계(07_api, 08_infra, 09_screen-design)를 그대로 따랐다. 읽기 API 3개, 컨테이너 둘(client, server), 포트 127.0.0.1:8000.
  • 점수와 순위는 저장하지 않고 API가 응답을 만들 때 계산한다. LLM을 부르지 않는다.
  • result/에서 docker compose up --build로 수집부터 화면까지 돌렸다. 키가 없어도 저장된 결과로 화면이 나온다. 테스트 37개가 통과한다.
  • README는 과제를 읽은 방식 → 가설과 생각의 변화 → 결론의 순서이고, 다이어그램 다섯 개를 넣었다.
  • 남은 것: 회계 공고의 골든셋 기대 하나가 결과와 어긋난다(70점과 77점). 로그는 설계의 일부만 남긴다. 둘 다 README와 CHECKLIST.md에 적었다.
