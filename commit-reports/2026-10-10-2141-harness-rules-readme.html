보고서 작성: 2026-10-10 21:41

무엇을

하네스에 검증, 브랜치 전략, 테스트 시나리오와 골든셋, 인프라 분리 규칙을 더했다. 루트에 README.md 초안을 만들고, 듀데이트를 2026-10-11 20:00으로 확정했다.

왜

01_problem으로 넘어가기 전에 하네스에서 정해지지 않은 것을 정리했다. README는 제출물이고 사용자의 생각을 담아야 하므로, 결정이 나올 때마다 바로 반영하도록 지금 틀을 만들었다.

어떻게

  • 검증: 만든 에이전트가 검증하지 않는다. 단계 폴더마다 전문가 역할의 서브에이전트가 검증하고, 결과는 15_report에 쓴다.
  • 테스트 시나리오: 13_e2e를 13_test-scenario로 바꿨다. 목업 이력서는 골든셋으로 보고 golden-set/에 둔다. 코드보다 먼저 확정하고 코드에 맞춰 고치지 않는다.
  • 인프라: 코드 폴더에 infra/를 더하고 local/(Docker Compose)과 server/(Pulumi)로 나눴다. 이번 과제는 로컬만 만들고, server/에는 비운 이유만 적었다.
  • 브랜치: 전략은 Git Flow이고 이유는 GitHub Actions CI/CD다. 이번 과제는 배포할 곳이 없어 CI/CD를 구성하지 않는다. 지금 개발 중인 버전이 v1.0.0이므로 v1.0.0 브랜치에 커밋한다.
  • 일하는 방식: 시간 배분과 우선순위는 사용자가 정한다. 하위 폴더가 있는 단계는 하위 폴더마다 설계 문서가 하나다.
