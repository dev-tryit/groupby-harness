고객사 프로그램(수집, 읽기)과 특징 추출 구현

보고서 작성: 2026-10-11 17:55 · 브랜치 v1.0.0

무엇을

백엔드에 고객사 프로그램(수집 → OCR → 넘기기)과 서비스 제공사 프로그램(특징 추출)을 만들었다. 공고 주소 두 개로 처음부터 끝까지 돌렸다.

왜

사용자가 OCR과 조건 추출을 먼저 만들자고 했고, 고객사 쪽을 CLI 프로그램으로 나누자고 했다.

어떻게

  • client/: 공고 주소에서 제목과 본문 이미지를 HTTP 요청으로 가져오고, 이미지를 잘라 gpt-4.1-mini로 읽고, 제목과 읽은 내용을 넘긴다.
  • server/: 넘겨받은 제목과 읽은 내용에서 직무와 그 직무의 담당업무, 자격요건, 우대사항, 참고사항을 뽑는다. 이미지는 보지 않는다.
  • 뽑은 항목이 읽은 내용 안에 글자 그대로 있는지 코드로 대조한다. 개인 사정(병역 등)은 코드가 참고사항으로 고정한다.
  • 헥사고날 구조다. 안쪽(도메인, 포트, 흐름)은 파일과 사람인과 OpenAI를 모르고, 어댑터가 맡는다.
  • 결과: 마케팅은 자격요건 5, 참고사항 1. 회계는 자격요건 3, 우대사항 2, 참고사항 2. 이미지와 결과 데이터는 git에 올리지 않는다.
  • 알릴 것: 04~13 단계의 설계 문서 없이 먼저 만들었고 테스트가 아직 없다.
