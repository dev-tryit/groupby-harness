코드 폴더를 서브모듈로 분리

보고서 작성: 2026-10-10 22:01 · 브랜치 v1.0.0

무엇을

docs/14_code의 frontend/, backend/, infra/를 각각 별도 public 레포로 만들고 서브모듈로 연결했다. 제출 시점에 main에 병합하는 규칙과 README의 폴더 구성 설명을 더했다.

왜

코드 레포를 각각 관리하기 위해서이고, GitHub Actions를 환경마다 다르게 설정할 일이 많기 때문이다. 워크플로는 레포 단위로 설정된다.

어떻게

  • 레포 3개(dev-tryit/groupby-frontend, groupby-backend, groupby-infra)를 만들고, 서브모듈이 v1.0.0 브랜치를 따르게 했다.
  • infra/local/과 infra/server/README.md는 groupby-infra 레포로 옮겼다.
  • 코드를 고치면 서브모듈에 먼저 커밋·푸시하고, 그다음 이 레포에서 가리키는 커밋을 갱신한다.
  • 제출 시점에 v1.0.0을 main에 병합한다. 평가자가 여는 기본 브랜치가 main이기 때문이다.
  • README에 git clone --recursive 명령과, 폴더 구성과 그렇게 짠 이유를 적었다.
